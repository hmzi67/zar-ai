# wheat_v2 few-shot controls: rust or field?

The few-shot adaptation raised NWRD stripe-rust recall from about 5% to about 98%
(experiments/wheat_v2_fewshot_nwrd.md). NWRD has no healthy images, so that alone can't tell a
model that learned stripe rust from one that learned "this looks like an NWRD photo". These
controls test that. Generated by `python -m zarai.vision.fewshot_controls` from the MLflow
experiment `wheat_v2_fewshot_controls`; criteria are fixed in
`configs/vision/wheat_v2_fewshot_controls.yaml` before running. Don't edit between the markers.

## Interpretation (written by hand from the tables above)

The adapted models did not learn stripe rust. They learned "NWRD field photo, or anything
rust-coloured, is yellow_rust". Five of the six criteria fail, and the evidence agrees:

- **The lesions barely matter.** With the marked rust inpainted, recall is still 0.91–0.93,
  against 0.98 intact. Before adaptation the model at least looked at rust (Grad-CAM lift 2.77;
  its peak was on rust in 46% of tiles). After adaptation the lift falls below 1 (0.77–0.85), so
  the CAM sits on rust less than chance, with the peak on rust in only 8–9% of tiles.
- **Field leaf without marked rust is called yellow_rust 55–62% of the time.** That is up from 2%,
  and it rises with k. Some of these tiles may hold unmarked rust, so this is an upper bound. But
  the ablation and Grad-CAM results don't depend on the masks being complete.
- **Brown rust is wiped out.** Pooled-test brown_rust recall falls from 0.93 to 0.06–0.08, and
  87–90% of brown rust images are now called yellow_rust. Black rust (11–12%) and septoria (5–7%)
  leak into yellow_rust too. Pooled macro-F1 falls from 0.943 to about 0.71. The earlier few-shot
  report measured only healthy false positives, which hardly moved (1.7% → 2.5%), so it missed this.
- **The Ethiopia transfer "pass" is not evidence of rust learning.** Ethiopian stripe rust goes
  from 0 to 0.93, but Ethiopia has no brown rust to tell the two hypotheses apart. Healthy leaves
  called a disease also rise (3% → 11%), and septoria recall falls (0.24 → 0.15). That fits "more
  rust-like things become yellow_rust" just as well.

So step 3 (keeping an adapted model as `wheat-vision@field-candidate`) was not done. The
selection run still wrote its pick (k = 50, draw 3, chosen on the adapt split) to
`experiments/runs/fewshot_controls/best_adapted.pt`, which is git-ignored. It is not registered or
served, and can be deleted.

What could work instead: adapt with brown and black rust in the batch (not only yellow_rust +
healthy), so the model must keep them apart. Also add NWRD-like field photos of other diseases and
healthy leaves. Then re-run these same controls unchanged.
